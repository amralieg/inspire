# Genie Code instructions for Inspire use-case notebooks

The notebooks in this folder were generated by Databricks Inspire AI. Each notebook is a tested skeleton for one use case: run controls, a data readiness gate, evaluation against a baseline, model registration, the business output writer, explanations, a summary for the decision owner, operationalization and a final contract check are already written.

## What to change
- Fill only the cells whose title contains GENIE SLOT. Keep their function names, arguments and return columns exactly as written; the other cells call them.
- Never edit cells marked "Inspire, do not edit", never rename the notebook, never change thresholds in code, and never create, update or delete jobs yourself. The "1. Run controls" cell runs the notebook as a tagged job.
- The "Genie Code instruction" cell is the brief for that notebook. Follow it for table choices, joins, the outcome rule and the method.

## How to run while you work
- Set the Execution widget to Here and the Smoke test widget to true while you fill and debug the slots.
- Run the notebook from the top after every change. Read the error, fix the slot that caused it, run again.
- When the smoke run passes, set Smoke test to false and run again. Then set Execution to As job.

## Definition of done
- The last cell, "12. Contract check", prints "Contract check PASSED".
- If it prints FAIL, fix the slot code it points to. Do not edit the contract check.

## Stop rule
- InspireReadinessStop means the data cannot support the use case today. Stop, show the user the printed message, and do not lower thresholds, fabricate data, drop checks, switch tables or edit the gate to force a pass. Thresholds change only through the readiness_overrides widget, which is logged.
- InspireNoChampion ("No approved model yet") and InspireRejected are also final answers for that run. Report them; do not bypass them.

## Data rules
- Read only the tables in SPEC["source_tables"] and join them only along SPEC["join_path"], the verified join path the Genie Code instruction cell describes.
- Every feature for an as-of date uses only data observed strictly before that date (no leakage). Evaluation is time-aware; never split randomly across time.
- Never fabricate unobserved inputs: no random numbers standing in for missing data. Seeded sampling and seeded simulation are allowed.
- Never write numbers you did not compute from the data into markdown, comments or output tables.
- Choose the simplest method that beats the baseline. No deep learning.

## Databricks serverless rules
- Do not use .cache(), .persist(), .unpersist(), .checkpoint(), sparkContext, RDDs or spark.databricks.* configs.
- Use fully qualified table names. When a slot needs a Python package the base environment lacks, add one pinned `%pip install name==version` line to the "Pinned packages" cell (create that cell as the first code cell if the notebook has none). That is the only edit allowed outside the GENIE SLOT cells.

## AI functions
- Use ai_query with failOnError => false, a responseFormat JSON schema and a max_tokens model parameter, on the top rows only. Use the endpoint in the ai_endpoint widget.
- Priority tiers and recommended actions are rule-based; never ask a model to assign them or to rate its own confidence.
